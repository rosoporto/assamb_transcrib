# assemblyai-cli — транскрибатор на AssemblyAI

CLI (Python, Typer + Rich), который превращает видео и аудио в текст с таймкодами через
[AssemblyAI](https://www.assemblyai.com/docs): один кроссплатформенный инструмент для файлов
и YouTube-видео.

Пример результата:

```
[00:00:00] Первый абзац распознанного текста. Он начинается с таймкода и заканчивается
на границе предложения или после паузы в речи.

[00:00:17] Следующий абзац идёт с новым таймкодом. С опцией --speakers в начале абзаца
добавляется метка вроде «Спикер A:».
```

---

## Для пользователя

### Что нужно
- Python 3.10+ и [uv](https://docs.astral.sh/uv/) (`pip install uv` или установщик с сайта).
- Интернет и аккаунт AssemblyAI. **Распознавание платное, списывается с вашего аккаунта.**
- `ffmpeg` для работы **не нужен**: файлы уходят в AssemblyAI как есть, а звук из YouTube
  скачивается готовым аудиопотоком.

### Установка
```bash
cd cli
uv sync
cp .env.example .env        # затем впишите свой ключ
```
Ключ берётся на https://www.assemblyai.com/dashboard (поле API Key). В `.env`:
```
ASSEMBLYAI_API_KEY=ваш_ключ
```
Проверка ключа (бесплатный запрос):
```bash
uv run python main.py key
```
Ожидаемый ответ: `API-ключ принят.`

### Транскрибировать файл или папку
```bash
uv run python main.py file "путь/к/файлу.mp3"
uv run python main.py file ./мои_видео          # все подходящие файлы папки
```
Результат — `ГОТОВЫЕ_ТЕКСТЫ/<имя файла>.txt` (папка создаётся рядом с `main.py`).
Исходные файлы не изменяются и не удаляются.

Форматы: `mp3 mp4 m4a mov mkv avi webm wav aac flac ogg opus mpeg mpg`.

### Транскрибировать YouTube
```bash
uv run python main.py youtube "https://www.youtube.com/watch?v=..."
uv run python main.py youtube "https://youtu.be/..." -y     # без вопроса про оплату
```
Работает с обычными ссылками, `youtu.be`, Shorts и записями завершённых эфиров. Обрабатывается
**одно** видео (даже если в ссылке есть `list=`). Идущие эфиры отклоняются. Видео должно быть
доступно без входа в аккаунт. Звук скачивается во временную папку и удаляется сразу после
распознавания.

Если YouTube ругается на JS-runtime, поставьте `deno` или `node` — yt-dlp найдёт их в PATH.

### Опции (общие для `file` и `youtube`)
| Опция | Что делает |
|---|---|
| `-o, --output-dir ПАПКА` | куда класть `.txt` (по умолчанию `ГОТОВЫЕ_ТЕКСТЫ/`) |
| `-l, --language КОД` | `auto` (по умолчанию, автоопределение) или `ru`, `en`, … |
| `--speakers` | метки спикеров: `[00:01:10] Спикер A: …` |
| `-t, --terms "А,Б,В"` | термины и имена, которые модель часто путает (`"ChatGPT,Claude Code,OpenCode"`) |
| `--force` | перезаписать уже готовый `.txt` |
| `-y, --yes` | (только `youtube`) не спрашивать подтверждение платного запуска |

Уже готовые тексты пропускаются без повторной оплаты. Чтобы обработать заново — `--force`.

### Сколько это стоит
После каждого файла и по итогам пакета печатается расход:
```
Потрачено: 15.7 мин ≈ $0.0391 (оценка, $0.15/ч)
```
**Это оценка, а не данные из сервиса:** API AssemblyAI стоимость не возвращает, программа
умножает длительность аудио на тариф за час. По умолчанию тариф `$0.15/ч` (Universal-2, значение
взято по памяти, уверенность средняя). Сверьте с https://www.assemblyai.com/pricing и при
необходимости задайте в `.env`:
```
ASSEMBLYAI_PRICE_PER_HOUR=0.21
```
Точный остаток и реальные списания — только в дашборде AssemblyAI. На длинных пакетах ориентируйтесь на него.

### Если что-то не так
| Симптом | Что делать |
|---|---|
| `Ключ не найден` | нет `.env` или пустая строка `ASSEMBLYAI_API_KEY` |
| `AssemblyAI отклонил ключ` | скопируйте ключ из дашборда целиком, проверьте `main.py key` |
| `Связь прервалась… Повтор через N с` | норма: загрузка повторяется до 3 раз, опрос статуса — до 5 |
| Долго нет ответа на загрузке | сетевая операция ограничена 90 с; при зависании сработает повтор |
| `Ошибка: AssemblyAI вернул пустую транскрибацию` | в файле нет речи (тишина/музыка) |
| В тексте перепутаны термины | добавьте их через `--terms` |
| YouTube: 429 / «подтвердите, что вы не бот» | подождите, смените сеть/ссылку; приватные ролики недоступны |

Подробный журнал: `transcription.log` рядом с `main.py` (время, файл, id задания, язык, секунды,
оценка стоимости, ошибки). Ключ в журнал и сообщения об ошибках не попадает.

Код возврата: `0` — всё хорошо, `1` — были ошибки, `2` — неверная настройка (ключ, формат),
`130` — остановлено Ctrl+C (готовые тексты сохраняются).

## Для разработчика

### Структура
```
cli/
  main.py            весь код (Typer-приложение)
  tests/test_main.py юнит-тесты без сети
  pyproject.toml     зависимости: typer, rich, assemblyai, yt-dlp, python-dotenv
  .env / .env.example
```

### Поток обработки (`transcribe_one`)
1. `upload_with_retries` → `upload_file`: загрузка файла **напрямую через httpx** на
   `POST {base_url}/v2/upload` с явным `Content-Length` (до 3 попыток, пауза 5·N с).
2. `transcriber.submit(upload_url, config)` — создаётся платное задание, id пишется в лог
   (`SUBMITTED`).
3. `wait_with_retries` → `transcript.wait_for_completion()`; при сбое сети опрос продолжается
   **по тому же заданию** (до 5 раз) — повтор не создаёт дубль.
4. `format_transcript` собирает абзацы по словам с таймкодами и атомарно пишет `.txt`
   (`*.part` → rename).
5. Возвращаются секунды аудио (`audio_duration`) для расчёта стоимости.

Ретраится только загрузка и опрос, но **не** `submit`: повтор создания задания мог бы
оплатить распознавание дважды.

### Решения и грабли
- **Своя загрузка вместо `Transcriber.upload_file` из SDK.** Встроенная на этой сети зависла на
  15 МБ с `The write operation timed out` (curl те же файлы грузил за ~20 с). Подмена на httpx с
  `Content-Length` работает. Причину зависаний окончательно не доказали: было ещё одно
  зависание уже на нашей загрузке, после чего та же загрузка проходила за 5–8 с, то есть,
  вероятно, нестабильна и сама сеть. Поэтому таймаут `NETWORK_TIMEOUT = 90` и ретраи.
- **`aai.settings.base_url` без `/v2`.** Путь загрузки строится как `{base_url}/v2/upload`.
- **SDK 1.x** (`assemblyai==1.10`): `TranscriptionConfig(language_detection=True | language_code=…,
  speaker_labels=…, keyterms_prompt=[…])`. Старый модуль `assemblyai.prerecorded.v2` (SDK 0.x)
  в 1.x отсутствует.
- **Стоимость оценочная** (`DEFAULT_PRICE_PER_HOUR`), API её не возвращает.
- **Абзацы:** новый абзац при паузе ≥ 1,8 с (`PAUSE_MS`), смене спикера, либо на конце предложения
  при ≥ 40 слов или ≥ 30 с; жёсткий предел 100 слов.
- **Имена файлов:** `safe_name` убирает эмодзи и запрещённые символы, обрезает до 180 знаков.
  Если в папке два файла с одинаковым именем без расширения (`a.mp3` и `a.mp4`), второй
  пропускается с предупреждением, иначе результаты перезаписали бы друг друга.
- **Секреты:** `scrub()` вырезает ключ из логов и ошибок, `err()` дополнительно экранирует
  rich-разметку, чтобы `[...]` в тексте ошибки не ломали вывод.
- Прогресс yt-dlp отключён (`noprogress`), иначе засоряет вывод.

### Известные ограничения
- Файл целиком грузится одним запросом (потоково, без загрузки в RAM, но без докачки при обрыве).
  Если обрыв произошёл на загрузке, она начнётся сначала.
- Нет докачки частичных результатов и параллельной обработки файлов (идут по очереди).
- YouTube: одно видео за вызов, звук проходит через диск (временная папка), а не через RAM.
- Тариф не обновляется автоматически, ключ хранится в открытом `.env`.
- Журнал `transcription.log` не ротируется.

### Тесты
```bash
uv run --with pytest python -m pytest -q -p no:cacheprovider
```
Покрыты без сети: таймкоды, разбиение на абзацы, метки спикеров, запасной формат без слов,
оценка стоимости, имена файлов, скрытие ключа, атомарная запись. Сетевую часть (загрузка,
задание, YouTube) тестами не покрыта: проверялась реальными прогонами (аудио 15,7 мин и Shorts
60 с).

### Как расширять
- Новая опция распознавания: параметр в `make_transcriber` → `aai.TranscriptionConfig(...)`;
  список допустимых полей смотрите в `aai.TranscriptionConfig.__init__`.
- Другой формат вывода (`.srt/.vtt`): слова с `start/end` в мс уже есть в `transcript.words`,
  нужен только новый форматтер рядом с `format_transcript`.
